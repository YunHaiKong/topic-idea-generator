# Contributing

Thanks for considering a contribution to this WorkBuddy skill.

## What this skill does

`(fill in on first commit)`: One-sentence summary, e.g., "Generates 30 cross-platform content topics from a single domain input."

## Repo layout

```
SKILL.md                    # The skill entry point (skill-creator managed)
references/                 # Docs loaded into the agent's context on demand
assets/                     # Files copied to the agent's output, not loaded
scripts/                    # Optional executable helpers
<name>.zip                  # Distributable bundle, regenerated by every release
.github/
  workflows/validate.yml    # Auto-validates SKILL.md on push
```

## Workflow

1. Fork the repo.
2. Create a feature branch: `git checkout -b feature/your-change`.
3. Edit files inside the skill directory:
   - `SKILL.md` for prompt / workflow tweaks (must keep imperative voice and the 5-section layout).
   - `references/` for documentation loaded by the agent at runtime.
   - `assets/` for SVG / template files.
4. Run the local validator:
   ```bash
   python ~/.workbuddy/plugins/cache/workbuddy-builtin/skill-skill-creator/0.1.0/scripts/package_skill.py . /tmp
   ```
5. Regenerate the zip — this is required. Every release commit ships the zip as a sibling of the source.
   ```bash
   python ~/.workbuddy/plugins/cache/workbuddy-builtin/skill-skill-creator/0.1.0/scripts/package_skill.py . .
   ```
6. Open a Pull Request. The `validate` workflow will run automatically.

## Style rules

- SKILL.md must use imperative voice ("Collect input", not "Collects input").
- YAML frontmatter must include `name`, `description`, and `agent_created: true` (set to false on first upstream release).
- Workflow section must be numbered 1..N.
- Every listed input must have a default behavior or a clear ask policy.
- Do not commit secrets, API keys, or private user data.

## Releasing

Maintainers trigger releases via the GitHub UI:

1. Draft a new release from `main`.
2. The release form is auto-populated from `.github/RELEASE_TEMPLATE.md`.
3. Bump the version in SKILL.md frontmatter (when present).
4. The zip in the root is the artifact users install via the marketplace import flow.
